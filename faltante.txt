SECCIÓN 2: CAMBIOS REALIZADOS EN ESTE PR (MARZO 2026)
================================================================================

Los siguientes problemas fueron detectados y corregidos automáticamente:

[CORREGIDO] 1. CARPETA ARCHIVE/ RESIDUAL EN PROYECTO 1
   - Problema: Existía una carpeta archive/CMaps/ con archivos que no deberían
     estar en un portafolio profesional:
     * archive/CMaps/x.txt        → Archivo de datos sin nombre (RUL data)
     * archive/CMaps/readme.txt   → Readme de la carpeta archive
     * archive/CMaps/Damage Propagation Modeling.pdf → PDF del dataset NASA
   - Por qué es un problema: Una carpeta llamada "archive" en un portafolio
     indica código/archivos sin limpiar. Los reclutadores técnicos notan esto.
   - Solución: Eliminada toda la carpeta archive/ con git rm -r.

[CORREGIDO] 2. ARCHIVO predict SIN EXTENSIÓN .py EN PROYECTO 2
   - Problema: Proyecto 2/src/predict era un script Python válido pero sin
     extensión .py. Esto es un error de principiante que llama negativamente
     la atención en un portafolio que pretende ser de nivel Senior.
   - Impacto: El archivo no es reconocido como Python por editores, GitHub,
     y herramientas de análisis estático.
   - Solución: Renombrado a predict.py con git mv.

[CORREGIDO] 3. ARCHIVO PORTFOLIO_TRANSFORMATION.MD EN RAÍZ
   - Problema: PORTFOLIO_TRANSFORMATION.md era un documento interno que
     describía "cómo se transformó el repositorio". Un portafolio profesional
     no debe mostrar sus procesos internos al reclutador/cliente.
   - Por qué es un problema: Hace el repositorio verse "en construcción".
     Un senior muestra el resultado final, no el proceso de limpieza.
   - Solución: Eliminado con git rm.

[CORREGIDO] 4. ARCHIVO RUL_FD002.txt INCONSISTENTE EN PROYECTO 1
   - Problema: El archivo data/raw/RUL_FD002.txt contenía datos del motor
     FD002 del dataset NASA CMAPSS. El proyecto usa principalmente FD001
     y los archivos procesados (data/processed/) solo contienen datos FD001.
     RUL_FD002.txt era un residuo que no se usa en el pipeline actual.
   - Solución: Eliminado con git rm. Se mantienen FD001, FD003, FD004 que
     son parte legítima del dataset completo CMAPSS.

[CORREGIDO] 5. DASHBOARD_ACCESS.md CON TEXTO INCORRECTO
   - Problema A: La línea 174 decía "All three dashboards are production-ready
     prototypes" cuando el portafolio tiene CUATRO proyectos con dashboard.
   - Problema B: La sección "Dashboard Features" en inglés solo listaba
     Proyectos 1, 2 y 3 pero omitía el Proyecto 4 por completo.
   - Problema C: La sección "Features del dashboard" en español solo listaba
     Proyectos 1 y 2, omitiendo Proyectos 3 y 4.
   - Solución: Corregido "three" por "four", agregado Proyecto 4 en sección
     English features, y agregados Proyectos 3 y 4 en sección Español features.

[CORREGIDO] 6. README DE PROYECTO 2 CON ESTRUCTURA INCORRECTA
   - Problema: La sección "Project Structure" mostraba:
     * requirements  (sin extensión .txt)
     * src/predict   (sin extensión .py)
     Ambos nombres eran incorrectos respecto a los archivos reales actuales.
   - Solución: Corregido a requirements.txt y predict.py respectivamente.

[CORREGIDO] 7. FALTA DE CONTRIBUTING.md A NIVEL RAÍZ
   - Problema: No existía ningún archivo de guías de contribución. Para un
     portafolio Senior, tener CONTRIBUTING.md demuestra madurez profesional
     y familiaridad con estándares de proyectos open-source.
   - Solución: Creado CONTRIBUTING.md con secciones de: cómo reportar issues,
     cómo hacer PRs, guías de estilo Python/notebooks/documentación, checklist
